# Agent Note: The Git graph panel resolves its own workspace and draws lanes as SVG

Status: implemented

English | [中文](2026-09-13-git-graph-workspace-scope-and-lanes.zh.md)

## Problem

The browser Git panel (`@deepseek-ai/dsh-client-ui-git-graph`) shipped with three defect clusters, all reproduced against the code:

- **Scope.** The registration's inject face resolved the target workspace as `items[0]?.workspaceId` of the Workspace Controller snapshot, and the component read the path it displayed as `items[0]?.path` from a second, independent read of the same snapshot. There was no way to point the panel at another workspace, and because `refresh` closed over the stable inject face, its `useEffect` never re-ran when the workspace list changed: switching workspaces in the sidebar left the panel showing the previous repository's history.
- **Identification.** `@deepseek-ai/dsh-workspace-git` parsed `git status --porcelain=v1 -z` as one NUL-separated record per entry, but a rename or copy emits two (the source path follows its record and the `->` form is dropped), so a rename produced a phantom row whose status pair was the first two bytes of a file name. Every repository verb ran with the workspace directory as its working directory while Git reports status paths relative to the work-tree root, so in a workspace that is a subdirectory of its repository `git add -- <reported path>` failed with `fatal: pathspec 'sub/z.txt' did not match any files`. `branches` read the attached branch from `%(HEAD)`, which yields the synthetic `(HEAD detached at …)` name on a detached HEAD. `graph` ran `git log` without `--topo-order`, whose reverse-chronological order does not guarantee that a commit precedes its parents. `operationInProgress` stat'ed the raw output of `git rev-parse --git-path`, which Git prints relative to the command's working directory, so the merge/rebase guard never fired. A directory outside every work tree was indistinguishable from a failed read.
- **Rendering.** Lane assignment set the commit's own column to its first parent unconditionally, so a parent that already owned a column left one commit waiting in two columns at once and drew a trunk no commit ever resolved. The lane area width came from counting the continuing columns instead of taking the largest column, so a free column between two occupied ones lost its width. Each row drew its own fixed-height columns inside a list with a 2 px gap, which cut every trunk in two. Trunks were painted in one neutral token regardless of column, dots punched a hole with a box-shadow ring that mismatched the row's hover fill, and a commit whose parent sat in another column had no connector at all.

## Decision

Both packages now carry the contract the panel needs, and the panel resolves its own scope.

**The Host owns Git's text formats.** `@deepseek-ai/dsh-workspace-git` gained `src/porcelain.ts`, a dependency-free module holding `parseStatus`, `parseBranches`, `parseGraph`, `parseWorkTree`, `parseHead`, `parseBranch`, and `assertRelativePath`; `src/index.ts` is subprocess glue over it. `parseStatus` folds a rename's second record into its entry as `origPath`. The work-tree probe's answer is read from stdout rather than from an exit status, and a refusal that names no repository is the one failure text matched — under a probe-only `LC_ALL=C` environment, because Git states a repository's absence in a message rather than in a status code. Every repository verb resolves `rev-parse --show-toplevel` once and runs from that root, which makes a reported path usable unchanged as a mutation target and repairs the branch-in-another-worktree comparison.

**`graph` answers with the repository, not only with commits.** `GitGraphView` is `{ repository: GitRepositoryView | null, entries: GitGraphEntry[] }`; `repository` carries the work-tree root, the HEAD hash, and the attached branch, and `null` is the definitional answer that the directory is outside every work tree. The panel therefore distinguishes "not a repository" from "the read failed" without matching error text. `branches` returns `GitBranchEntry` with `current: null` while HEAD is detached, `status` entries carry `origPath`, and `--topo-order` is unconditional: lane assignment depends on a commit preceding its parents, so the flag is a correctness requirement rather than a deployment choice, and `Config` is unchanged.

**The panel resolves its scope from the framework hooks.** `resolveWorkspaceId(workspaces, currentSessionId, sessionsById, preferred)` follows the workspace of the session being worked in — matched by the session's recorded directory, the rule workspace navigation already uses — honors an explicit choice while it still names a registered workspace, and falls back to registry order. The component reads the choice through the global `useWorkspaces` and `useSessions` seats; the inject face carries the Remote verbs alone and no longer resolves an id. A scope change resets the panel and rereads it, and a sequence counter discards any answer that started before the newest read, including a rejection.

**Lanes are a pure model drawn as SVG.** `src/client/graph.ts` holds `graphRows`, which releases the commit's column before placing its parents, so a parent that already owns a column keeps it; each row reports its lane, whether a trunk reached it from above, the columns that cross it, and the column each parent is drawn into. `laneCount` takes the largest drawn column plus one. `connectorPath` and `laneCenter` live beside the geometry constants, and the component injects `ROW_HEIGHT` into the list as `--graph-row-height` so the stylesheet and the drawing read one number. Trunks carry their column's palette color, a branch tip has no line above its dot, non-first parents get a vertical-tangent curve, and dots are plain filled circles, which removes the hover halo.

**Discard is offered only where Git can restore.** `statusMeta` returns `discardable`, false for untracked entries, because `git restore --worktree` cannot remove a path Git does not track.

## Alternatives considered

- **Keep the panel scoped to the first workspace and only fix the reread.** The smallest change, but it leaves the reported defect — no way to choose the workspace — in place, and the two independent `items[0]` reads would have kept disagreeing about which repository is on screen.
- **Publish the resolved workspace as a new global seat from `ui-workspace`.** That package is upstream-owned and outside this distribution's fork set; a shared seat would have made it a seventeenth divergent package for one panel's benefit. The two framework hooks already expose every fact the rule needs.
- **Give the panel its own `repository()` verb instead of an envelope on `graph`.** A fourth RPC per refresh, and it re-introduces the ordering question the envelope answers: status and branches are only meaningful once a repository exists, and a probe that answers after them cannot classify their failures.
- **`git log --all`.** Considered and declined: this distribution's owner asked for the HEAD-reachable history, with other branches identified and switched from the branch card. The host README records the consequence.
- **Draw lanes with one positioned `<div>` per column, as before.** The vertical trunks survive that, but connectors between columns do not: a curve is what an SVG path expresses directly, and the row-tiling fix depends on geometry the component and the stylesheet both read.
- **Promote the workspace chooser to `ui-primitives`.** The promotion rule fires when a second package needs a control; the sibling panel that would justify it (`ui-workspace-inspector`) is out of this change's scope, and the chooser is composed from the shared `Menu` primitive rather than restating it.
- **Cap the number of ref labels per commit row.** Rejected in favor of clipping one line with the full list in the row's tooltip: a cap is a tunable, and the tooltip keeps every label reachable.

## Consequences

- The panel now follows the session being worked in and can be pointed anywhere; the choice lives in the component, so reopening the settings panel returns to the session's workspace. The README records that limitation.
- A workspace that is a subdirectory of its repository shows paths relative to the repository root — the paths its own mutations accept — rather than paths relative to the workspace.
- `@deepseek-ai/dsh-workspace-git` gained its first tests (`tests/porcelain.spec.ts`, `tests/service.spec.ts` over real temporary repositories) and both packages are at 100 % per-file coverage; `parseWorkTree`'s repository-absent match and `operationInProgress`'s non-ENOENT `lstat` arm are the two arms pinned by real Git and by a documented `v8 ignore` respectively.
- The `graph` verb's answer changed shape, so the generated Typert artifacts were rebuilt; the client half depends on that regenerated `lib/typert.remote-client.d.ts` and adds `@deepseek-ai/dsh-workspace-git`, `@deepseek-ai/dsh-client-ui-session`, `@deepseek-ai/dsh-api-session-controller`, and `@deepseek-ai/dsh-session` as type-only development dependencies.
- No session log, agent-loop, or model-visible surface changed, and the panel registers no model-visible content, so no recorded-session snapshot was added or re-recorded.

## Testing

`pnpm run test:gui` covers both packages. The Host suite drives real `git` in temporary repositories — rename decoding, subdirectory workspaces, a merge's parent ordering, a detached HEAD, an unborn branch, a directory outside every work tree, a worktree holding a branch, a merge in progress, and a workspace directory Git cannot run in — and skips on a host without Git. The client suite pins the lane model and the drawing it produces: trunk columns, the curve a merge draws, a tip with no line above its dot, the injected row height, the workspace a session resolves to, a reread on a scope change, a discarded answer for an abandoned scope, and the failure of one facet leaving the others intact.

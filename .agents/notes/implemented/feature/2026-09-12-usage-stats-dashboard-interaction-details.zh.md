# Agent Note: 用量仪表盘就地揭示每一个图表数值

Status: implemented

[English](2026-09-12-usage-stats-dashboard-interaction-details.md) | 中文

## Problem

用量仪表盘此前把历史记录呈现为单向的图：读者想核对的每一个数值——某一天用了多少 Token、尖峰由哪个桶造成、某个模型的份额如何算出——只能在别处找：热力图格子的原生 `title`、趋势图上方的摘要行，或折叠面板之后的表格。同类参考实现会在读者视线所在处给出答案，而设置内容列已经有空间这样做。

## Decision

`@deepseek-ai/dsh-client-ui-usage-stats` 让每个数值由绘制它的元素就地揭示，并让每张卡片拥有管束自己的查看状态。

概览数值改为一条带分隔线的长条，数值在上、标签在下。被紧凑写法丢掉了精度的数值，改为以悬停与聚焦提示给出精确值，而不是复述屏幕上的数字；最常用模型移到呈现它的圆环旁边，使长条只承载所选范围的五项合计。范围行现在点明管束其下所有卡片的控件。

活动网格按范围最大值的三等分为格子着色，并让读者选择格子报告什么：当天、包含它的那一周（自周一开始），或截至当天的累计值。每个格子在悬停或键盘聚焦时打开详情卡，并以精确的日期、Token 与消息数为自己的无障碍名称。

趋势卡片把范围画成每个 Token 桶一条折线，或画成每日堆叠柱。两种形态共用同一批按天划分的悬停列，因此悬停或聚焦揭示同一张详情卡、放置同一条十字准线，并标出当天每个非零桶的取值；指向图例项会让其余序列后退。绘图盒固定为 `0 0 100 100`，配 `preserveAspectRatio="none"` 与非缩放描边，因此折线与堆叠柱都不需要卡片的像素宽度。

模型圆环改为每段一条描边弧线，而不是用 `stroke-dasharray` 位移，因此弧段的指针区域正是读者看到的那一段；指向排行行或弧段会互相高亮。

`@deepseek-ai/dsh-client-ui-primitives` 的 `Tooltip` 现在接受节点型 label，而不再只接受字符串。仪表盘的两张详情卡都是节点，而锚点测量、定位、视口收敛与上下翻转本就由该原语承担。它的气泡不接收指针事件——这正是图表悬停提示需要的：`HoverCard` 是指针可停留、可复制的预览卡，且它的块级锚点包装会破坏这些格子所在的网格与列布局。

每个切换都属于它管束的卡片：着色指标归活动网格，绘图形态归趋势卡片。范围与扫描方式一律未变。

## Alternatives considered

**改为扩展 Host 快照，而不是浏览器侧**——本次刻意不做，但并非出于原则。累计 Token、峰值日、最长会话、最长连续天数，以及全年活动序列都需要新的 Host 字段（其中最长会话还需要新的按会话墙钟时间折叠），这会改动 wire 契约、typos 生成的 Remote 产物以及已录制的 golden。这些数值本身值得单独加入；它们并不是揭示仪表盘已收到数值的前提。

**画带星期行的周列日历**——否决，因为 7 天或 30 天的范围填不满一张，而周列网格只会用到内容列约三分之一宽度，同时缩小悬停目标。密集方格保留了足够大的可指目标；格子所属日期来自其无障碍名称与详情卡。

**按模型画趋势线（如同参考实现）**——当前 wire 无法支持：Host 分别按天与按模型聚合 Token，从不按“某天 × 某模型”。四个 Token 桶才是快照真正携带的按天序列，因此图例与详情卡的行都命名桶。模型归属留在数据支持它的圆环与排行中。

**在图表旁保留一个本地提示组件**——否决，属于重复实现：锚点测量、视口收敛与翻转都是原语的职责，第二份副本必然漂移。把 `Tooltip.label` 放宽为节点是增量改动：所有既有调用点都传字符串，且没有新增分支。

**让活动网格的周起点跟随区域设置**——否决，改为固定周一。这样每周指标只取决于日期，并有单元测试钉住；跟随区域设置会让同一份日志的“本周合计”因读者而异。

**给图例加键盘停留点**——否决：图例唯一的行为是一次临时的视觉强调，而仪表盘的键盘路径已经能通过每个日期列与明细表读到同样的数值。增加五个没有动作的停留点得不偿失。

## Consequences

仪表盘画出的每个数值都能在它被画出的地方读到，且每张详情卡的紧凑数值都由同一元素的精确无障碍名称兜底。录制的 Web golden 现在带有每天一个具名格子、每天一个具名列，因此这些交互与其他页面部分处于同一套无密钥证据之下。

卡片各自持有切换项，因此切换范围会保留读者选定的指标与绘图形态。详情卡按设计是临时且不可交互的：其中的内容无法被选中、复制或聚焦——这正是表格仍然是批量读取数值的表面的原因。

仪表盘仍只请求 7 天或 30 天的 Host 数据，并且不呈现 Host 未提供的任何数值。想在此寻找累计值或全时段数值的评审不会找到，README 的已知限制也写明了这一点。

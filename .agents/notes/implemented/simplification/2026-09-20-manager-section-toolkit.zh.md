# Agent Note: 管理器设置区块共用一套工具

Status: implemented

[English](2026-09-20-manager-section-toolkit.md) | 中文

## 问题

MCP 服务器管理器与技能管理器各有一个设置区块：经线路读取一份列表、提供「用户或某个工作区」的作用域、支持检索、并报告加载失败。两份并排写出，于是同一套管道长了两遍：一套会让被取代的回复作废的读取生命周期、一个基于工作区列表的作用域选择器、一行工具栏，以及加载与失败分支。跨文件克隆检测在两者之间报出十处重复；而且两份副本已经漂移：两个区块在宣告某行操作的结果时，把字典键传进了一个参数语义为「宣告文案」的辅助函数，于是 toast 渲染出 `toastEnabled` 而不是字典里那句话。

## 决定

`@deepseek-ai/dsh-client-ui-primitives` 承载两个区块都需要的机械部分，与它们本就共用的 `SectionChrome`、`SearchField` 放在一起：

- `useRemoteList(list, scope)` 持有一份列表的生命周期——最新一次读取获胜，变更以 Host 返回的回复对齐而不是预测结果，忙碌标记由最后收尾的那次回复结束。
- `useScopeChoice(workspaces)` 持有作用域选择：区块读取的那个联合类型（`ManagerScope`）、选择器当前的值，以及「所选工作区并不在列表里」这一状态。它对结果做记忆化，因为区块正是按这个身份去读自己那份列表。
- `ScopePicker`、`SectionToolbar`、`SectionState` 是这些值渲染出的三段区块框架：触发器与其工作区菜单、工具栏行（选择器、搜索框、尾部控件），以及「加载／失败／主体」的切换。
- `sectionToolbarLabels(t)` 从区块自己的翻译座位上读取工具栏文案。它需要的六个键合成一个 `SectionToolbarKey` 联合，于是这些名字只写一次，而不是在每个调用点重拼；两个管理器字典本来就发布它们。

各管理器保留属于自己的部分：自己的 Remote 动词与线路类型、自己的字典、自己的行与对话框。

## 考虑过的替代方案

**用 `jscpd:ignore` 标记这两份平行实现。** 仓库的忽略标记是为「无法复用的、刻意镜像的代码」准备的——例如复刻某个原语 hook 的定位逻辑。这里的机械部分是普通的、可复用的 React 与状态，标记它只会掩盖一次真正的抽取。

**给这套工具单开一个包。** 第三个管理器区块出现时，仍然只是五个导出的三个调用方；客户端插件之间共享的控件就该住在 primitives 包里，而两个区块本就共用它的两个组件。

**让每个区块各自传一个 label 对象给工具栏。** 否决：那六个键名会在每个调用点重拼一遍，而这次改动要消除的正是这种重复。

## 后果

管理器包没有新增依赖——读取回复按结构声明，因此 primitives 依然不依赖线路协议包。`ManagerScope` 与两个包各自为自己的动词声明的联合类型结构一致，因此区块直接透传；线路契约仍属管理器。行操作的 toast 现在渲染文案而不是字典键，而这正是调用点一直以来想要表达的意思。

## 测试

`useRemoteList` 覆盖首次读取、读取失败、被变更作废的回复、成功与失败的变更、重复的宣告、会随作废回复结束的忙碌状态，以及切换作用域后重新读取。`useScopeChoice` 覆盖开局状态、解析出的工作区、回到用户作用域、列表未提供的选择，以及它必须跨渲染保持的身份。`ScopePicker`、`SectionToolbar`、`SectionState` 覆盖各自的渲染状态与上报的选择。两个管理器区块套件——覆盖开关、对话框与失败的那两个设置界面——原样通过。
